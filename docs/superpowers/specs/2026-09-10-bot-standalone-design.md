# Развод бота и сканера + починка рассылки

Дата: 2026-09-10
Статус: утверждено владельцем

## Задача

Бот по фандингам используется регулярно, сканер — нет. Сейчас бот не может жить без
сканера: он берёт данные из `http://127.0.0.1:8000/api/bot/all`. Нужно сделать бота
самодостаточным, выключить сканер без удаления и починить всё, что аудит нашёл по боту.

## Что решено

- **Архитектура A**: общий пакет `exchanges/`, собственный цикл обновления внутри бота,
  служба сканера остановлена и снята с автозапуска. Код сканера остаётся рабочим.
- **OKX**: опрашивать монеты с объёмом ≥ минимального порога среди пользователей
  (сейчас 262 из 463), раз в 180 секунд. Батча у OKX нет — проверено на живом API
  (`Parameter instId error`), поэтому вопрос только в частоте и охвате.
- **Таймзона**: четверым пользователям без таймзоны проставить UTC+3.
- **Репозиторий**: остаётся публичным.

## Архитектура

```
exchanges/           общий модуль (используют и бот, и сканер)
  types.py           Rec: exchange, symbol, funding_pct, next_ms, mark_px,
                     vol_usdt_24h, link
  binance.py         fetch(client) -> dict[symbol, Rec]
  bybit.py
  gate.py
  okx.py             fetch(client, symbols=None): списком берёт цены и объёмы,
                     фандинги — поштучно по переданному отбору

market.py            кэш рынка внутри бота: два темпа обновления, статусы бирж
bot.py               хендлеры и рассылка, читает market вместо HTTP
web.py               сканер: импортирует exchanges/, свои 4 биржи держит у себя
```

Формат `Rec` совпадает с тем, что раньше отдавал `/api/bot/all`, поэтому форматирование
строк, Δ% и группировка в боте не меняются — меняется только источник данных.

### Темпы обновления

| Группа | Период | Запросов за цикл |
|---|---|---|
| Binance, Bybit, Gate, цены и объёмы OKX | 60 с | 7 |
| Фандинги OKX поштучно | 180 с | ~262 |

Около 1,6 запроса в секунду против нынешних ~32.

Отбор монет OKX: `vol_usdt_24h >= max(500_000, min(порог объёма по всем пользователям))`.
Порог пересчитывается перед каждым медленным циклом. Нижняя граница в 500k защищает от
пользователя, поставившего ноль.

### Обработка сбоев

Ошибка биржи не затирает её прошлые данные — запись помечается устаревшей, в кэше
остаётся последний удачный снимок. Логика взята из `refresh_loop` сканера, где она уже
работает правильно.

## Правки по боту (из аудита)

### Рассылка

1. **Длинный дайджест режется на части.** Общая функция `split_html_chunks(text, limit)`
   вместо нынешнего `send_split`, работающего только с `Message`. Дайджест дополнительно
   ограничен 20 строками на биржу — так же, как кнопка «ТОП».
2. **Ошибка одного пользователя не трогает остальных.** `try/except` вокруг тела цикла
   по каждому пользователю, а не вокруг всего прохода.
3. **Пользователь, заблокировавший бота**, помечается `notify_enabled = 0`, чтобы бот не
   стучался к нему каждый час.

### Данные пользователей

4. **Пороги санируются при загрузке и при вводе.** Отрицательный порог не может быть
   положительным числом: `neg = -abs(neg)`, `pos = abs(pos)`. Это чинит пользователя
   `7202439497`, из-за которого сейчас падает вся рассылка.
5. **Пользователи грузятся из базы при старте.** Сейчас словарь в памяти наполняется
   только при входящем сообщении, поэтому после рестарта дайджест идёт лишь тем, кто сам
   написал боту.
6. **Пустая таймзона заменяется на UTC+3** при загрузке, разово в базе для четверых.
   Защита от `None` в `/me` и в клавиатуре фильтров остаётся на случай новых пользователей.

### Часовой тик

7. **Триггер по смене часа, а не по точному совпадению минуты.** Дайджест уходит, когда
   локальное время пользователя дошло до целевой минуты и за этот час ещё не отправлялось.
   Сейчас подвисание цикла на минуту стоит пропуска целого часа.

### Прочее

8. Убрать лог-шум: отметка о пропуске по неподходящей минуте и лог каждого HTTP-запроса.
9. Убрать мёртвый `delta_block` и висячий пробел в конце строки.
10. Дописать `requirements.txt`: `aiogram`, `python-dotenv`.

## Тесты

Тесты на чистые функции, стандартный `unittest`, без новых зависимостей:

- санитайзер порогов: `+1.0 / +1.0 → +1.0 / -1.0`;
- `split_html_chunks`: длинный текст режется по строкам, разметка не рвётся,
  каждая часть укладывается в лимит;
- `passes_threshold`, `is_clean_symbol`, `calc_coin_width`, `format_item_line`;
- триггер часа: срабатывает один раз за час, переживает пропуск минуты;
- слияние кэша рынка: ошибка биржи не затирает прошлые данные.

## Выкат

1. Локально: тесты зелёные.
2. Пуш в GitHub, `git pull` на сервере.
3. `systemctl stop scanner-web && systemctl disable scanner-web`.
4. Разовая правка базы: таймзона UTC+3 четверым, санитайз порогов.
5. `systemctl restart scanner-bot`, проверить журнал.
6. Лимит на journald (`SystemMaxUse=500M`) — журналы разрослись до 3,9 ГБ.

Откат: `systemctl enable --now scanner-web` и `git checkout` предыдущего коммита.

## Чего не делаем

- Не трогаем разбор ответов бирж — код проверен двумя месяцами работы.
- Не переписываем веб-морду сканера и его четыре биржи.
- Не меняем формат сообщений бота: пользователи к нему привыкли.
